# Quick Deploy 운영 가이드

Quick Deploy는 패키지 파일명에서 서비스와 버전을 식별한 뒤 관리자가 등록한 서비스 배포 프리셋의 대상을 사용합니다. 브라우저의 분석 결과는 안내용이며 API가 업로드 시 파일명과 활성 설정을 다시 검증합니다.

## 파일명 규칙

```text
<artifact-prefix>-v<semver>.tar.gz
```

- 접두어: 소문자 ASCII 영문·숫자, 내부 하이픈, 최대 64자
- 버전: leading zero가 없는 SemVer core와 선택적 prerelease
- 확장자: 대소문자를 구분하는 `.tar.gz`
- 허용 예: `ai-portal-v2.4.1.tar.gz`, `ai-portal-v2.4.2-rc1.tar.gz`
- 거부 예: `AI-Portal-v2.4.1.tar.gz`, `ai_portal-v2.4.1.tar.gz`, `ai-portal-v01.2.3.tar.gz`

Quick Deploy는 현재 운영 버전보다 SemVer 우선순위가 높은 **순방향 배포**만 허용합니다. 예를 들어 현재 버전이 `2.4.1`이면 SemVer상 더 낮은 `2.4.1-hotfix1`은 사용할 수 없으므로 `2.4.2-hotfix.1`처럼 다음 버전을 사용해야 합니다. 이전 버전 복구는 릴리즈 상세의 명시적 복구 절차를 사용하여 감사 이력과 검증 기준을 유지합니다. 기존 운영 버전이 SemVer가 아니라면 운영자 고급 등록으로 SemVer 기준 버전을 한 번 배포한 뒤 Quick Deploy를 사용하십시오.

## 관리자 준비

관리자 화면의 **서비스 배포 프리셋**에서 다음 값을 연결합니다.

1. 사용자에게 표시할 프리셋 이름과 고유 아티팩트 접두어
2. 활성 애플리케이션과 해당 애플리케이션의 활성 환경
3. 같은 애플리케이션·환경에 연결된 활성 배포 프로필
4. 승인 후 자동 배포 사용 여부

배포 프로필에는 Registry credential, 승인된 배포 스크립트, Health Check와 Runner label을 먼저 구성해야 합니다. 승인 필요 여부는 전역 승인 설정, 보호 환경과 배포 프로필 정책을 합쳐 서버가 결정합니다.

## 사용자 흐름

1. **새 버전 배포**에 패키지를 끌어 놓습니다.
2. 자동 인식된 서비스, 대상 환경, 현재 버전과 신규 버전을 확인합니다.
3. **배포 요청**을 누릅니다.

승인이 필요하면 릴리즈는 검토 대기로 이동합니다. 승인이 필요하지 않으면 배포 작업이 즉시 생성됩니다. 프리셋의 승인 후 자동 배포가 켜진 경우 승인과 작업 생성은 원자적으로 처리되어 중간의 `APPROVED` 상태에 멈추지 않습니다.

기존의 애플리케이션·환경·배포 프로필을 직접 선택해야 하는 작업은 **고급 등록** 화면에서 계속 사용할 수 있습니다. 따라서 기존 설치를 업그레이드한 직후 프리셋을 아직 만들지 않았더라도 운영 흐름이 중단되지 않습니다.

## 변경 안전성

- 사전 확인 이후 프리셋이 비활성화되거나 대상 연결이 바뀌면 업로드를 거부합니다.
- 릴리즈를 만든 뒤에는 그 릴리즈가 확정한 애플리케이션·환경·프로필을 사용하며, 이후 프리셋 변경을 다시 해석하지 않습니다.
- 같은 애플리케이션·환경·버전의 중복 요청은 충돌로 처리합니다.
- 일반 릴리즈와 Quick Deploy 모두 기존 SHA256, 안전한 tar 검사, Runner/Executor 격리와 감사 로그를 그대로 사용합니다.

현재 권한 모델의 릴리즈 권한은 서비스별이 아니라 전역입니다. 서비스별 **내 서비스** 권한 범위를 도입하기 전에는 `releases.create`/`releases.submit` 권한을 신뢰할 수 있는 배포 요청자에게만 부여하십시오.
